## 🧮 Multiple Linear Regression

The project uses **Multiple Linear Regression** to model the relationship between multiple independent variables and a continuous target variable.

The general equation is:

```text
ŷ = β₀ + β₁x₁ + β₂x₂ + β₃x₃ + ... + βₙxₙ
```

Where:

* `ŷ` = predicted value of the target
* `β₀` = intercept
* `β₁, β₂, ..., βₙ` = regression coefficients
* `x₁, x₂, ..., xₙ` = input features

Each coefficient represents the estimated contribution of a feature while accounting for the other variables in the model.

## 💻 Implementation

The model is implemented as a **Python `.py` script** rather than a Jupyter Notebook.

### 1. Import Libraries

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
```

The project uses NumPy, Pandas, Matplotlib, and Scikit-learn.

---

### 2. Import the Dataset

The dataset is loaded using Pandas.

```python
dataset = pd.read_csv("MultipleLinearRegression/50_Startups.csv")

X = dataset.iloc[:, :-1].values
y = dataset.iloc[:, -1].values
```

Here:

* `X` contains the independent variables.
* `y` contains the target variable, `Profit`.

---

### 3. Train-Test Split

The dataset is divided into training and test sets using an **80/20 split**.

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    train_size=0.8,
    random_state=0
)
```

The `random_state=0` ensures that the same split can be reproduced.

---

### 4. Encoding the Categorical Variable

The `State` feature is categorical and needs to be converted into a numerical representation.

A `ColumnTransformer` with `OneHotEncoder` is used:

```python
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder

ct = ColumnTransformer(
    transformers=[
        (
            'encoder',
            OneHotEncoder(
                handle_unknown='ignore',
                sparse_output=False
            ),
            [3]
        )
    ],
    remainder='passthrough'
)
```

The `[3]` specifies the fourth column, which corresponds to the `State` feature.

`handle_unknown='ignore'` allows the encoder to safely transform a category that may appear in the test data but was not present in the training data.

---

## 🔐 Preventing Data Leakage

One of the most important concepts demonstrated in this project is **preventing data leakage**.

The encoder is fitted **only on the training data**:

```python
X_train = np.array(ct.fit_transform(X_train))
```

The test data is then transformed using the **same fitted encoder**:

```python
X_test = np.array(ct.transform(X_test))
```

### Why?

`fit_transform()`:

* Learns information from the training data.
* Applies the transformation.

`transform()`:

* Does not learn anything new.
* Applies the transformation using what was already learned.

The correct approach is therefore:

```text
Training Data
     ↓
fit_transform()
     ↓
Learn categories + transform


Test Data
     ↓
transform()
     ↓
Transform using learned categories
```

The test set must not be used to learn preprocessing parameters.

This prevents information from the test set from influencing the model during training.

## 📈 Training the Model

The Multiple Linear Regression model is created using Scikit-learn:

```python
from sklearn.linear_model import LinearRegression

regressor = LinearRegression()
regressor.fit(X_train, y_train)
```

The model learns the relationship between the startup characteristics and their corresponding profits using the training data.

---

## 🔮 Making Predictions

The trained model is used to predict profits for the test set:

```python
y_pred = regressor.predict(X_test)
```

The predictions are then compared with the actual profit values:

```python
np.set_printoptions(precision=2)

print("Predicted Profit  Actual Profit")

print(
    np.concatenate(
        (
            y_pred.reshape(len(y_pred), 1),
            y_test.reshape(len(y_test), 1)
        ),
        axis=1
    )
)
```

This produces a side-by-side comparison:

```text
Predicted Profit    Actual Profit
```

## 🧠 Key Concepts Learned

### 1. Feature Scaling Isn't Always Necessary

One important lesson from this project was that **feature scaling is not always required**.

For ordinary Multiple Linear Regression, scaling the input variables is generally not necessary for the model to work correctly.

The coefficients adjust according to the scale of their respective features.

This reinforced an important principle:

> **Preprocessing decisions should depend on the algorithm rather than being applied automatically.**

Feature scaling can be important for other algorithms, but it should not be treated as a mandatory preprocessing step for every Machine Learning model.

---

### 2. Handling Categorical Variables

The `State` feature is categorical, so it cannot be directly used by the regression model in its original form.

I explored **One-Hot Encoding** to represent the categorical values numerically.

When using one-hot encoding with an intercept, using **n−1 dummy variables** can avoid redundant information and perfect multicollinearity.

This is commonly referred to as avoiding the **dummy variable trap**.

---

### 3. Preventing Data Leakage

Data leakage was one of the most important practical concepts I learned from this project.

The general principle is:

> **Anything that learns from data should learn only from the training set.**

The correct sequence is:

```text
Split Data
    ↓
Fit preprocessing on Training Data
    ↓
Transform Training Data
    ↓
Transform Test Data using learned parameters
    ↓
Train Model
    ↓
Evaluate on Test Data
```

If preprocessing is fitted using the complete dataset before the train-test split, information from the test set can influence the model-building process.

This can make model performance appear better than it actually is.

---

### 4. Feature Selection

I also explored different feature-selection strategies to determine which variables should be retained.

The approaches explored include:

* **All-in**
* **Forward Selection**
* **Backward Elimination**
* **All Possible Models**

The objective is not simply to create a model containing the maximum number of variables.

Instead, the goal is to identify a model that provides:

* Useful predictive performance
* Meaningful business insight
* Appropriate model complexity
* Relevant features

Feature selection therefore becomes both a statistical and business decision.
